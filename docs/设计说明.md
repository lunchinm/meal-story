# 《今天吃什么？——校园膳食调查簿》实现设计说明

> 依据：`meal-story/content/act1..4.json`（剧本唯一事实来源）
> 版本：2026-11-19 · 对应线上 `theme-inject.js?v=20261120h`

---

## 0. 一句话设计

剧本是一份带**显式字段**的结构化稿子（每句台词都写了它走哪个界面、谁说的、有没有知识卡），
所以这个作品的设计原则只有一条：**引擎按剧本字段跑，界面按剧本字段选**，不做猜测，也不把结构压平成纯对话。

---

## 1. 剧本数据模型

剧本共 **816 个节点**，12 种类型：

| 类型 | 数量 | 关键字段 | 作用 |
|---|---|---|---|
| `say` | 740 | `speaker` `channel` `scene` `expr` `actor` `card` `seg` `prop` | 台词 / 旁白 |
| `choice` | 33 | `question` `hint` `options[{text, reply, next}]` | 玩家选择 |
| `record` | 23 | `flag` `label` | 记一笔到调查簿 |
| `branch` | 6 | `rules` `fallback` | 按 flag 走不同去向 |
| `chapter` | 4 | `title` `subtitle` `image` | 章节卡 |
| `ending` | 3 | `title` `body[]` `action` `cards[]` `unlocks[]` | 结局页 |
| `plate` | 2 | `budget` `slots` `cards[]` `check` `tip` `hint` | 配一份午饭 |
| `evidence` | 2 | `prompt` `posterText[]` `regions[]` `claims[]` `need` `hint` | 宣传图核实 |
| `notebook` | 2 | `title` `entries[{label,text}]` | 调查簿成页 |
| `compare` | 1 | `offers[{name,front,back}]` `worse` `hint` | 瓶身对比 |
| `explore` | 1 | `title` `items[{label,summary}]` | 观察三件东西 |
| `random` | 1 | `pool[{id,next}]` | 随机小事件 |

`say` 里最重要的三个字段：

- `channel`：`chat` 161 句 / `stage` 399 句 / 空 180 句
- `speaker`：角色名，或 `旁白`
- `card`：`k1/k2/k3`，共 7 句知识要点

## 2. 界面分层：一句台词该去哪里

| 剧本条件 | 界面 | 配音 |
|---|---|---|
| `channel == chat` | 群聊面板 | **不配** |
| `channel == stage` 或空 | 下方文本框（纸卡） | 配音 |
| `speaker == 旁白` | 文本框 | 配音 |
| `channel == chat` 且 `speaker == 你` | 群聊 · 回复条 → 右侧绿气泡 | 不配 |
| `card != 空` | 文本框 + 知识卡标记 | 配音 |

实现方式：`tools/export-line-meta.py` 把 739 条台词导出成 `LINE_META["说话人|台词"] = {c: 是否聊天, k: 卡片级, s: 段落}`，
运行时按**当前这句**查表决定界面，不依赖背景图、不依赖时间。

配音侧：`convert-to-webgal.py` 只在「不是 chat」且「mp3 真实存在」时才写 `-vocal=`；
剧本引用了但音频表缺失的 4 句（`a1-62/72/80`、`a4-revise1`）会被自动跳过。

## 3. 群聊界面

- 面板固定在右侧，米色纸面，顶栏「校园膳食调查组」
- 气泡：对方左对齐 + 姓名；玩家右对齐 + 绿色纸底 + 署名「我」
- **图片消息**：整张缩略图作为一条消息留在历史里（不再只是文字按钮），点开大图，点空白关闭
- **玩家的话不直接出现**：先以底部纸签（回复条）形式给出，点一下才“发送”→ 纸签消失、右侧绿气泡出现、剧情自动推进一句
- 同一句只落一次（`sentKeys` + 末句去重），不会重复

12 条图片消息的文本 → 图片映射由 `tools/sync-chat-images.py` 导出（`CHAT_IMAGES`）。

---

## 4. 文本框界面

- 左下角色名牌 + 米色纸卡正文，行距按阅读节奏放大
- 选项：**纸签精确覆盖在引擎选项条目上**（纸签 `pointer-events:none`，真实点击落到引擎条目）
  —— 这样既保持纸面风格，又不会出现「画得好看但点不动」
- 原生对话框与纸卡都设 `pointer-events:none`，点击只用于推进，避免「点空白重播上一句语音」

---

## 5. 互动节点：剧本里被压平的部分，现在各有界面

剧本 11 个互动节点，各有纸面面板（左上），字段原文照搬：

| 节点 | 界面内容 |
|---|---|
| 翻阅（explore） | 标题 + 三样东西的 `label` / `summary` |
| 核实（evidence） | 宣传图 4 行文字（可疑行标红）+ 需圈几处 + 提示 |
| 调查簿（notebook） | 每条 `label` + `text` |
| 配餐（plate） | 预算 12 元 / 4 格 + 全部菜品标签 |
| 对比（compare） | 两瓶的正面 / 背面文案 |
| 结局（ending） | 结尾正文 + 「明天可以做的一件事」+ 解锁清单 |

数据由 `tools/export-ui-data.py` 导出为 `UI_DATA[题目文本]`，运行时按当前台词命中即展开。

## 6. 状态与分支（当前实现程度）

| 机制 | 现状 | 说明 |
|---|---|---|
| `record`（23 条） | **未入账** | 现在只是台词；计划做成「已记入调查簿：xx」的即时提示 + 调查簿页 |
| `branch`（6 处） | 线性（走 `fallback`） | WebGAL 无条件表达式，需要转换器把 `rules` 编译成 `choose` 或变量判断 |
| `random`（1 处） | 未实现 | 计划构建期随机取值并记录种子 |
| `ending.cards/unlocks` | 只展示文字 | 缺卡片排版素材 |

这三项是**目前唯一明显偏离剧本语义**的地方，已列入下一轮。

## 8. 架构：WebGAL 引擎 + 自绘主题层

```
content/act*.json          剧本（唯一事实源）
   │ convert-to-webgal.py
   ▼
webgal-game/scene/*.txt    WebGAL 脚本（含 label / choose / changeBg / vocal）
webgal-game/theme-inject.js 自绘层：群聊、纸卡、纸签、互动面板、跳关
   │ CI: patch-engine.py → 打补丁 → 构建
   ▼
dist  →  GitHub Pages
```

引擎补丁出口（自绘层能用到的东西）：

| 出口 | 用途 |
|---|---|
| `__wgBackToTitle()` | 回标题（原生按钮点不动，需程序触发） |
| `__wgClosePanels()` | 关掉原生面板，避免盖住自绘层 |
| `__wgNext()` | 主动推进一句（回复条发送后自动往下走） |
| `__wgJump(label, scene?)` | 跳 label（同一场景内） |
| `__wgStopVocal()` | 立刻停上一句配音 |
| `__wgDebugStart` | 开局直接进入指定场景 + 段落（跳关用） |

## 9. 调试工具：跳关

- 转换器为每章（`label:actN`）与每段（`label:segN_M`）打 label，导出 `webgal-game/jump.json`（**20 个节点**）
- 运行时左下角有一个很淡的「跳关」按钮，点开列出 20 个段落（章 + 首句预览）
- 点条目 → 设置 `__wgDebugStart` → 回标题 → 重新开局到该段落
- 这样做是因为运行中的 `changeScene` 在等待输入时会被引擎锁住，跨场景跳不稳；「重开到段落」最可靠

## 12. 设计取舍记录

- **不删台词**：所有 `say` 都进脚本；只通过界面与配音开关表达差异
- **不做纯自定义引擎**：WebGAL 负责存档 / 回想 / 流程图，自绘层只接管视觉与交互细节
- **可点性优先**：任何“纸签”都必须是外观层，点击永远落到引擎真实控件上
- **调试优先**：跳关、`jump.json`、每段的 label 都为了能快速核对剧本某一段，而不必从头点
