# 剧本对照审查（v4.0 实现 vs 《今天吃什么》全章剧本）

审查对象：`content/act1-4.json`（788 节点）、`src/modules/*`、`src/engine/*`、`assets/*`
剧本依据：`文档/今天吃什么全章剧本.txt`（2144 行，四章 21 个场景）

---

## 一、剧本要达成的意图

| 章 | 意图（剧本原文要点） | 关键机制 |
| --- | --- | --- |
| 一 | 用群聊里的宣传图引出“核实来源 → 看全天饮食 → 问需求”三步；章末用**摊开的调查簿**收束三条记录，可点每条看解释与来源 | 物件点击探索（宣传图/餐盘/便签）、调查簿、记录 3 条 |
| 二 | 三条角色分支（米粒/陆燃/周简）各自对应一种现实困难；科普量收进**可点击知识便签**；章末**给明天留一张便签**，只显示已体验角色 | 三分支、知识便签、回访选择、记录 3 条 |
| 三 | 三种回访承接第二章便签；三段标签调查（乳饮料归类／单位换算／无蔗糖与麦芽糖浆）；一次有生活目的的采购；**三个随机事件**等概率抽取、同局不重复、读档不重抽；环境点击、隐藏对话、第四章伏笔；包装统一标“教学示例” | 回访、标签三段、采购、随机事件池、偶遇记录、隐藏照片 |
| 四 | 小组讨论室整理三份资料；按第二章回访对象决定先展示谁的材料与默认试行对象，**可更换**；三结局互斥判定（隐藏→进阶→普通）；片尾四张知识卡带“查看依据”，片尾后解锁完整指南/角色记录/来源页 | 更换试行对象、个人条件便签、按反馈修订、结局相册 |

剧本对结局的判定写得很明确（2112—2127 行）：

- 普通：指南完成，场景四选“先发布通用版”
- 进阶：选试行 + 完成通用试行总结（有个人便签但没按反馈修订，仍算进阶）
- 隐藏：选试行 + **当前试行对象**的个人条件便签完成 + 按反馈完成个人方案修订
- 对象一致性：米粒的便签不能替代陆燃或周简；更换对象要重新核对

## 三、做错的

### 1. 立绘表情从未使用，且缺一种

剧本要求「普通、开心、疑惑、无语」四种表情，随台词切换。
实测：749 句台词的 `expr` 全部为空，立绘永远是普通表情；素材也只有三种（normal/happy/worried），没有“无语”。

### 2. 场景背景大面积错配

实测：`scene` 字段 722 句是 `class`（教室），仅 27 句 `chat`。
原因：转换器按场景标题关键词（群/食堂/便利店/教室）匹配，而剧本场景名多为“套餐本人有什么想说的”“先看哪里”“瓶子长得像，里面也一样吗”，全部落到默认值。
后果：食堂、便利店、课桌的戏都在教室背景上演。

### 3. 第一章的“物件点击探索”被替换成别的玩法

剧本（113—190 行）：三个物件可点击，每件首次点击播短对白，重复点击只给一句回顾；看完两个出现“和大家聊聊”；未点某项时补入对应对白。
实现：改成了“在宣传图上圈出两处夸大说法”的热区题，探索与回顾机制都没有，补充对白也没做。

### 4. 选择点与分支对白丢失严重

剧本：28 个【玩家选择】块、62 个“选项A/B/C”行。
实现：23 个选择点、27 个选项，多数选择点只剩 1 个选项；分支对白只保留 89 句。原文大量“选项—分支—汇合”的结构被压平成单线。

### 5. 结局判定与剧本完全不同，且隐藏结局正常游玩不可达

实现规则：`budget` + `early` 两个 flag → 隐藏；`compare:a3-it` → 进阶。
问题：`budget`、`early` 这两个 flag 在代码里**从未被设置**（模块只写 `evidence:`/`review:`/`compare:` 前缀），所以隐藏结局只能靠 `?node=e_hidden` 跳转看到，正常玩是拿不到的。
与剧本判据（发布通用版／试行／试行+个人便签+按反馈修订）没有对应关系。

### 6. 记录系统整个缺失

剧本有 32 条【记录“X”】（想省心、看过原图、问过需求、米粒方案三种、回访米粒/陆燃/周简、采购目的三种、个人条件便签完成、根据反馈完成修订……），是后续回访与结局判定的依据。
实现：`choice` 节点没有任何 `flag` 字段，交互关只写自造的 `review:id`/`compare:id`，没有任何一条剧本记录落地。

### 7. 第二章的三条角色分支没有实现

剧本：米粒/陆燃/周简三条独立分支，各自围绕不同困难展开，章末再让玩家“给明天留一张便签”（只显示已体验角色）。
实现：单线叙事 + 一个配餐关 + 一个记录关，分支结构与章末互动都不存在。

### 8. 知识便签与“查看依据”入口缺失

剧本：3 处【可展开知识便签】、章末【查看知识便签】、涉及科学结论处提供“查看依据”（343、493、598、711、812 行）。
实现：`card` 字段 0 处使用，`knowledge.json` 的 3 条内容没有任何节点引用——等于写了没接。

1. **调查簿界面**（326 行）：章末摊开的调查簿，三条记录可逐条点开看解释与来源，底部【继续第二章/翻看调查记录/保存并退出】

3. **章末便签互动**（759 行，第二章）
4. **第三章三段标签调查**：乳饮料归类、“4 为什么比 6 还多”单位换算、“无蔗糖”的另外半句话——目前只有 1 个对比关 + 1 个证据关
5. **随机事件池 R1/R2/R3**（1237—1330 行）：第二件半价、一袋分三份、瓶身只拍到一半；等概率抽取、同局不重复、读档不重抽、插入场景四后或场景六结尾
6. **偶遇记录**与通关后回看（1267、1301、1328、1388 行）
7. **隐藏对话《第四张照片》**（1353 行）：条件为点过苏桃旧照片 + 场景六选“先问需求” + 采购结束

11. **更换试行对象**（1645 行）与**个人条件便签、按反馈修订**——这是隐藏结局的核心链路
12. **结局相册与片尾四张知识卡**（2100—2109 行），每张带“查看依据”
13. **片尾后解锁**（1903、1959、2089 行）：完整通用指南、已体验角色记录、知识来源页

15. **演出音效**：快门声等（第三章苏桃拍照多次出现）

## 六、成因说明

主要是三处偷懒，不是剧本理解偏差：

1. **用关键词猜场景**，没有逐场景人工核对文案与背景映射
2. **把分支压成单线**（转换器只保留首句分支对白），导致选择与记录一起丢失
3. **结局与记录用了自造 flag**，没有按剧本的 32 条记录去串
