## 一、群聊界面：固定尺寸 + 自动滚动 + 底部发言

### 现在的问题

- `.phone` 高度跟着消息长，消息一多面板就往下撑，底部按钮被顶出屏幕
- 滚动只在渲染时设一次 `scrollTop`，新消息进来后没有动画，玩家容易错过
- 玩家自己的话混在列表里出现，没有“在底部发言”的感觉
- 选择点还是覆盖式面板，和聊天窗口割裂

### 目标形态

一个固定高度的聊天窗口，像真的群聊：

1. **面板尺寸不变**：宽 620px、高 520px（手机竖屏用 100vw × 62dvh），消息区内部滚动
2. **新消息自动落底**：插入后 `scrollTo({top: scrollHeight, behavior:'smooth'})`，180ms 内完成；玩家手动上翻时不打断（检测是否在底部 24px 内）
3. **玩家发言在底部**：右对齐绿色气泡，出现时带 120ms 的淡入上移
4. **选项做成输入栏**：聊天段的 `choice` 渲染成底部三条快捷回复，点了直接变成玩家气泡发出，再播对方反应
5. **滚动性能**：DOM 只保留最近 60 条，更早的进折叠区（“查看更早消息”）
6. **键盘**：空格/回车推进；选项焦点可用 ↑↓ + 回车

### 改动点

| 文件 | 改动 |
| --- | --- |
| `src/ui/stage.ts` | `sayChat()` 改成固定容器 + 增量 append，新增 `appendChat()`、`scrollToBottom()`、`chatChoice()` |
| `src/ui/styles.css` | `.phone` 固定宽高、`.phone-body` flex:1 + overflow、气泡入场动画、`.phone-choices` 底部条 |
| `src/engine/runner.ts` | 聊天段的 `choice` 走 `stage.chatChoice()`，选完先把选项文本作为玩家气泡插入 |
| `tools/e2e.mjs` | 新增：连点 20 条后 `.phone` 高度不变、`scrollTop` 在底部、选项条可点 |

### 验收

- 消息 5 条和 50 条时，面板高度完全一致
- 新消息出现后 200ms 内滚到底部
- 玩家消息始终右对齐且位于列表最后
- 1024×720 与 390×844 下不溢出、不用横向滚动

工作量：约半天。

## 二、立绘重抠：陆燃与罗师傅

### 现状确认

把三张立绘放到棋盘格上对比，能看到：

- `ch_luran_*`：身体右侧有一整块浅蓝矩形，是生成时的背景块，抠图时被当成主体留下了
- `ch_luomaster_*`：肩后有一块浅绿矩形，同理

现有 `cutout.py` 的规则是「四角取背景色 → 距离阈值内且局部方差小的像素清空」，对**连到边缘**的背景能去掉，对**被主体包围或颜色接近但方差大**的块会漏。

### 修法（两档，先自动后重生成）

**A. 连通域清理（优先）**

1. 用四角+边缘采样估计背景色，得到容差范围
2. 对所有「接近背景色」的像素做连通域标记
3. 与画布边缘相连的连通域 → 直接清空
4. 不与边缘相连、但面积 > 画布 2% 且颜色方差 < 6 的连通域 → 也清空（这就是那两块方块）
5. 边缘 1px 羽化，避免锯齿和白边

**B. 重生成（兜底）**

提示词加强：`isolated on pure white, no backdrop, no color blocks, studio cutout`；
负向加 `color block, panel, frame, rectangle, gradient background`；
用与现有角色一致的种子族，保证画风统一。

### 验收

- 在棋盘格、深绿背景、照片背景三种底上分别截图，看不到方块边界
- 头发/衣角边缘无白边、无锯齿
- 12 张立绘统一复查（米粒、周简、许知夏、苏桃也顺带过一遍）

工作量：自动清理半天；若需重生成，另加半天（含挑图）。

## 三、可旋转饮料瓶（左键拖动看正反面）

### 目标

两个 500ml 瓶装饮料，左键按住左右拖动可以转动瓶身，看到正面、侧面、背面的配料表与营养成分表；松手有惯性，像拿着实物转。

### 三条技术路线

| 方案 | 做法 | 优点 | 缺点 | 包体 |
| --- | --- | --- | --- | --- |
| A. three.js 真 3D | 瓶身模型 + 圆柱体贴图，灯光一打即可 | 任意角度连续、真实感最好、标签能贴图 | 需要模型与贴图；three 核心约 +150KB gzip；渲染开销大 | +0.8～1.5MB |
| B. 预渲染转盘（推荐先做） | 离线渲染 16 帧（每 22.5°），拖动切换帧 | 实现简单、零依赖、帧率稳；画风与现有插画一致 | 角度离散；帧数少会“跳”；帧多则包体涨 | 16 帧 × 512×1024 webp ≈ 1.5MB |
| C. CSS 3D | 8 片薄片围成圆柱 | 无需额外依赖 | 接缝明显、文字会拉伸变形 | ≈0.6MB |

**建议**：先做 B 的 POC，两天内能摸到成品效果；如果老大觉得“转起来不够真”，再升级到 A。

### 交互设计（B 方案）

- `pointerdown` 记录起点，`pointermove` 累计水平位移 → `帧 = 起点帧 + 位移 / 12px`，循环取模
- 松手后按最后速度做惯性，每秒衰减到 30%
- 点击标签区域（正面/背面热区）→ 弹出可读的标签面板（复用现有 `prop` 面板，字号 14px 以上）
- 键盘 ←→ 也能转，触屏直接拖
- 两瓶并排，各自独立转动；顶部提示“按住左右拖动”

### 资产需求（给美术/生成用）

1. 瓶身造型：透明/磨砂塑料瓶、方肩或圆肩、瓶盖颜色与瓶身区分（两款要不一样）
2. 标签贴图：正面（品牌名+插画）、背面（配料表、营养成分表、净含量），文字最终用 HTML 叠加保证清晰
3. 转盘帧：16 帧、512×1024、透明底、灯光与相机固定、每帧 22.5°
4. 若走 A 方案：glTF 模型 + 2048×1024 的标签贴图

### 验收

- 拖动 360° 无跳帧、无接缝错位
- 惯性自然，停手后 1s 内静止
- 背面标签文字可读（放大面板里数字不能糊）
- 手机触屏可拖，不触发页面滚动
- 游戏中两瓶对比关（第三章）与标签关联动：转到位才能看到配料表

工作量：B 方案 POC 1 天、成品化 1 天；A 方案另加 2 天（建模+贴图+性能调优）。
